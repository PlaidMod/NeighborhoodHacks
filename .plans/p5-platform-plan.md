# P5 Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the shared platform that the other four parts run on: the Next.js app at the repo root, the Supabase database, security, shared server code, translations, the first two screens, the legal pages, demo mode and deployment.

**Architecture:** One Next.js 16 App Router app lives at the repo root, in the layout from `Technical_Implementation_Plan.md` §2. All data lives in Supabase Postgres. Browsers never read the database directly: server code uses the secret (service-role) key, and every table has Row Level Security (RLS) on with no policies, so the public key can read nothing. Shared code in `lib/` is plain TypeScript, so P1's and P2's command-line scripts can import it outside Next.js.

**Tech Stack:** Next.js 16.4.2, React 19.3.0, TypeScript 5.9 (strict), Tailwind CSS 4.3.3 (through `@tailwindcss/postcss`), shadcn/ui (radix-nova style), next-intl 4.x, @supabase/supabase-js 2.x, @supabase/ssr 0.12.x, @google/genai 2.x, zod 4.x, vitest, Supabase (Postgres with PostGIS and pg_trgm), Vercel.

**Conventions (shared contract; record in the handoff):**
- **Keys:**
  - `bodies.id` and `sources.id` are `text` slugs (for example `hcmud_489` or `hc_commissioners_court`). P1 confirms the body slugs, per scraper spec §12.7.
  - Every other table uses `id uuid primary key default gen_random_uuid()`.
- **Value lists:** `text` columns with `check (col in (...))`, only where the plan or spec lists the values. No Postgres enums.
- **Other types:**
  - times: `timestamptz`
  - JSON: `jsonb`
  - tax rates and money: `numeric`
  - shapes: `geometry(MultiPolygon, 4326)` with a GIST index; points: `geometry(Point, 4326)`
- **Foreign keys:**
  - `body_id text references bodies(id) on update cascade`
  - `items.meeting_id` references `meetings(id) on delete cascade`
- **Extensions:** `create extension if not exists postgis with schema extensions;` and the same for `pg_trgm`. That keeps `spatial_ref_sys` out of `public`. Trigram indexes use `extensions.gin_trgm_ops`.
- **RLS:** every migration ends with `alter table <t> enable row level security;` for each table it creates. Never `create policy`.
- **Version numbers:** after `apply_migration`, rename each local file to the version that `list_migrations` reports, so the files and the database agree. P5 applies teammates' later migrations the same way.
