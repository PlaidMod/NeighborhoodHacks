## Implementation and plan contradictions

- The plan's unconditional “closed → written/email” and late-alert wording are unsafe for bodies without verified alternatives. Only Harris Court has an explicit after-close written route here. UI and alerts must not promise written acceptance elsewhere.
- The prototype's generic MUD “no sign-up deadline,” generic school card sign-up, HISD written-comment claim, Harris ninth-floor location/1–3-minute allocation and Lone Star 6 PM/three-minute default are not used as registration authority.
- HISD “at least three business days” and CFISD “when agenda posted” cannot become exact opening timestamps. The engine returns `unknown`, preserves any known cutoff, and continues to expose official methods for user verification. No live availability check or holiday calendar feed is implemented.
- Tuesday Council public session and Wednesday voting are distinct. The resolver requires the actual comment session timestamp; upstream must map those meetings. Council's generic recipe is restricted to Tuesday (`meetingWeekday: 2`); other weekdays return unknown with no invented cutoff. Consolidated sessions must be individually checked. A future integration should carry session type and meeting-specific overrides rather than apply Tuesday rules to all sessions.
- `DeadlineRule` supports the plan's snake_case keys, optional explicit holidays, elapsed hours/minutes, and strict previous weekdays. Local day arithmetic uses America/Chicago including DST. Ambiguous/nonexistent local deadlines and invalid timestamps return unknown windows; no host timezone guessing.
- Lone Star's online/card rules differ. `RegistrationMethod.opensRule` / `closesRule` and `getMethodWindow()` preserve the known online opening and five-minute in-person cutoff independently. `availableMethods(recipe, state, meetingISO, now)` suppresses the card at its exact cutoff while online remains unknown; it suppresses expired oral/registration routes at meeting start. Only verified `availableAfterClose` written routes survive. The two-argument call remains compatible, but callers must pass meeting and clock to enforce method deadlines.
- HISD and CFISD use `minutes: null` because the actual allocation is conditional. `practiceMinutes: 1` is only a conservative rehearsal target and must be labeled that way. `meetingLocationText` supplies English/Spanish directions while the legacy `meetingLocation` string remains available.
- Node 24 built-in tests import `.ts` directly; the parent integration enables `allowImportingTsExtensions`. No database schema or global data type changes, no additional runtime dependencies, and no external submissions.
